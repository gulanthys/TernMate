# TernMate 产品需求

状态：首版已实现。本文定义用户可见行为；安装步骤和验收范围见[设计方案](design.md)。

## 目标与范围

面向在 Tern 中开发、用 omp 处理 GitHub 任务的开发者。工作单位是一个仓库中的一条 Issue 或 PR，不是 GitHub Projects 看板。成功标准：找到目标后只需一次点击，不复制链接、不再输入启动提示，便能在正确代码上下文中开始工作。

## 从筛选到继续工作

1. 从项目目录打开工作台。若 fork 和上游都可作为目标，选择一次；面板持续显示 `owner/repo`。无法关联本地仓库时提示选择，不在任意目录启动分析。
2. 切换 Issue / PR，选择快捷筛选或组合条件。显示生效条件、逐项移除和清空入口。快捷入口不是额外限制：用户可以查看不属于自己的开放项。
3. 单击一行或按 Enter 直接进入交互式 omp。方向键只移动选择。启动期间显示进度；重复点击不得创建第二个会话。
4. 返回列表后保留原仓库、筛选和位置。刷新后优先保留选中条目；若已不匹配，选相邻项。再次打开同一任务，应聚焦或恢复原会话。

## 列表与检索

| 类型 | 快捷入口 | 可组合条件 |
| --- | --- | --- |
| Issue | 全部开放、分配给我、我创建的 | 开放／已关闭、负责人、作者、标签、标题关键词、精确编号 |
| PR | 全部开放、我提交的、请求我审查、有未解决线程、CI 失败、我的待处理 PR | 开放／已合并／关闭未合并、草稿、作者、目标分支、标签、标题关键词、精确编号、审查与 CI 状态 |

不同条件取交集；“我的待处理 PR”特指**我提交的开放 PR，且有未解决线程或当前版本 CI 失败**。命中两者只显示一行并标明两种原因。收到审查请求不等于存在未解决意见。筛选面向整个目标仓库；加载中、部分结果、确认无匹配、无权限必须可区分。

## 点击后的任务契约

**Issue：先分析。** omp 获得标题、正文、讨论、来源链接和本地仓库。首轮输出区分用户报告、可定位的代码证据和待验证假设，并给出下一步。点击本身不授权修改；用户可在同一会话要求修复。

**PR：处理已有问题。** omp 在对应 PR head 的独立工作区中，针对未解决线程核对当前代码，区分需修改、已修未关闭、需要作者判断。针对 CI 定位失败检查、job、step 及可读日志；区分代码失败、基础设施问题与证据不足。可执行本地修改和针对性验证。报告应逐项说明处理结果；本地通过不等于远端通过。不得因打开 PR 自动推送、发评论、关闭线程、批准或合并。

## 首版验收场景

| 场景 | 可观察结果 |
| --- | --- |
| fork 中选择上游，点击分配给我的 Issue | omp 打开的编号和链接属于上游，结合代码给出分析，文件未被改动 |
| 唯一匹配项不在第一页 | 能找到该项；扫描结束前不显示“无匹配” |
| PR 同时有未解决线程和失败检查 | 待处理列表只出现一次；会话拿到两类证据，在正确提交上修复并验证，原工作区未变 |
| 上次 CI 失败，新 head 检查尚在运行 | 不标为当前失败；日志不可读时说明原因而不推断根因 |
| 连点同一 PR，关闭 omp 后再次打开 | 不重复创建；恢复原任务上下文，不误开同仓库的其他对话 |
| 本地修复未提交，远端 PR 有新提交 | 明示版本差异；不丢弃修改、不静默切换提交 |
| 离线、未登录或被限流 | 给出原因与可行的下一步；错误不伪装成空列表或 CI 通过 |

## 范围边界

首版优先保证选仓、筛选、任务会话和本地分析／修复。列表内批量管理、跨仓库通知、Projects 看板和自动回写 GitHub 不作为首版交付条件。
